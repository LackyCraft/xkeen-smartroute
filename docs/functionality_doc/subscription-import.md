## Формат входа

Подписка — это URL, отдающий **base64 от текстового блока строк**
`vless://...` / `trojan://...` (тот же формат, что понимает V2rayNG,
Happ, V2Box). `sr_import()` фетчит тело, пробует раскодировать как
base64, и если получившийся текст содержит `://` — использует его; иначе
считает, что сервер уже отдал обычный (не закодированный) текст:

```sh
raw="$(sr_fetch_sub "$client" "$url" "$os_ov" "$locale_ov" "$model_ov" "$ver_ov" "$hwid_ov")" || sr_die "failed to fetch subscription: $url"
decoded="$(printf '%s' "$raw" | base64 -d 2>/dev/null || true)"
case "$decoded" in
	*"://"*) body="$decoded" ;;
	*) body="$raw" ;;
esac
```

## Обход anti-bot защиты подписок (client presets)

Некоторые панели подписок (типичный `3x-ui`-based "collection"-эндпоинт)
по умолчанию отдают HTML-страницу для браузера, и только запросам,
которые выглядят как известное VPN-приложение (User-Agent + набор
заголовков `X-Device-*`), — настоящую подписку. `client_preset()` —
таблица пресетов, дающая `sr_fetch_sub()` весь набор заголовков сразу:

```sh
client_preset() {
	case "$1" in
		smartroute|"") echo "XKeen-SmartRoute/1.0 (+https://github.com/LackyCraft/xkeen-smartroute)|XKeen SmartRoute|ru||" ;;
		happ)          echo "Happ|iOS|ru|iPhone 15 Pro|17.5" ;;
		...
		*)             echo "$1|XKeen SmartRoute|ru||" ;;
	esac
}
```

([`lib/subscription.sh:53-76`](../../lib/subscription.sh#L53-L76))

Формат — `User-Agent|OS|Locale|Model|VerOs`. Любое из пяти полей можно
переопределить вручную (передав непустое значение соответствующего
override-аргумента) — UI это делает через "Настроить заголовки
устройства…" на форме импорта. Неизвестный `client` не считается
ошибкой — отправляется буквально как User-Agent (`*) echo "$1|..."`),
на случай экзотического провайдера вне списка.

`X-Hwid` (псевдо-ID устройства) — стабильный на один роутер, а не
случайный на каждый импорт: генерируется один раз в `client_hwid()` и
кешируется в `$SR_STATE_DIR/hwid`, потому что некоторые панели считают
активные подключения по hwid и не любят, когда он скачет.

**Держать в синхроне**: список пресетов дублируется в
[`gateway/static/app.js`](../../gateway/static/app.js)'s `CLIENT_PRESETS`
и в LuCI's `xkeen-smartroute.js` (UI показывает названия — backend
владеет реальными значениями заголовков, ключ пресета передаётся как
строка).

## Парсинг одной строки

`sr_import()` построчно проходит тело подписки. Строка без `vless://`
или `trojan://` префикса — пропускается (`skipped` счётчик, не ошибка —
разделители/комментарии в подписке не редкость):

```sh
case "$line" in
	vless://*) proto=vless ;;
	trojan://*) proto=trojan ;;
	*) skipped=$((skipped + 1)); continue ;;
esac
```

Дальше — ручной разбор URI без внешних библиотек (POSIX `sh`, никаких
`bash`-измов): `user@host:port?query#fragment` разбирается через
`${var%pattern}` / `${var#pattern}` подстановки
([`lib/subscription.sh:339-352`](../../lib/subscription.sh#L339-L352)).
`qval()` вытаскивает конкретный query-параметр (ещё в percent-encoded
виде), `urldecode()` — percent-decode + `+` → пробел, оба
POSIX-портируемые (без `bash`-массивов/regex-подстановок):

```sh
urldecode() {
	printf '%b' "$(printf '%s' "$1" | sed 's/+/ /g; s/%\(..\)/\\x\1/g')"
}

qval() {
	printf '%s' "$1" | tr '&' '\n' | sed -n "s/^$2=//p" | head -n1
}
```

([`lib/subscription.sh:103-111`](../../lib/subscription.sh#L103-L111))

`build_outbound()` собирает итоговый Xray outbound-объект из разобранных
полей — protocol-specific `settings` (vless: `vnext`+`users`, trojan:
`servers`+`password`), затем `streamSettings` по `security`
(`tls`/`reality`/`none`) и `network` (`tcp`/`ws`/`grpc`/`xhttp`), одним
`jq -n` вызовом ([`lib/subscription.sh:118-208`](../../lib/subscription.sh#L118-L208)).

## XHTTP `extra`: почему это не опциональное украшение

Провайдеры, использующие XHTTP-транспорт, иногда прикладывают query-параметр
`extra` — сырой JSON с настройками padding-обфускации
(`xPaddingBytes`/`xPaddingObfsMode`/...), переиспользования соединений
(`xmux`), чанкинга аплоада. Это реальное поле схемы Xray
(`SplitHTTPConfig.Extra json.RawMessage` в `infra/conf`), не наша
выдумка — настоящие клиенты (v2rayNG, Happ) передают его один в один.

Было подтверждено вживую: два узла, которые Observatory **и** прямой
ручной пробник (тот же GET через тот же outbound, в обход кеша
Observatory) стабильно считали мёртвыми, у Happ на той же сети работали
без проблем — единственное отличие было именно в этом поле. Без
`xPaddingObfsMode:true` TLS-рукопожатие завершается успешно, но
XHTTP-запрос никогда не получает ответ ("SSL - The connection indicated
an EOF" сразу после успешного TCP-коннекта).

```sh
extra_raw="$(urldecode "$(qval "$query" extra)")"
extra_json="$(printf '%s' "$extra_raw" | jq -c . 2>/dev/null)"
[ -n "$extra_json" ] || extra_json='null'
```

([`lib/subscription.sh:165-177`](../../lib/subscription.sh#L165-L177))

**Реальный баг, который тут был и починен**: `jq -c .` на пустом
stdin (нет `extra` у большинства узлов, особенно REALITY) завершается
**с кодом 0 и пустым выводом** — не ошибкой. Значит `|| echo 'null'`
никогда не срабатывал, `extra_json` оставался пустой строкой, и
`--argjson extra "$extra_json"` падал с "invalid JSON text" — что рушило
весь `build_outbound()` для этого узла целиком. Живьём это уронило
подписку со 130+ серверов до 26 (пропал вообще каждый узел без явного
`extra`). Проверка именно **пустоты вывода**, а не кода возврата,
закрывает оба случая (нет входа / битый вход) одинаково.

Если у какого-то конкретного узла комбинация полей внутри `extra`
не проходит валидатор Xray-конфига — `_sr_xray_validate()` в
`lib/common.sh` (см. [gateway-architecture.md](gateway-architecture.md))
не роняет весь конфиг, а срезает `.extra` только у этого одного
outbound-тега и повторяет попытку.

## Генерация тега: история трёх коллизий

Тег — не порядковый номер, а функция от **содержимого строки узла**.
Причина: подписка при обновлении возвращает те же узлы, но часто в
другом порядке/вперемешку с добавлениями — индекс-тег дрейфовал бы из-под
уже сохранённых в профилях ссылок при каждом refresh.

Финальная формула, после трёх реально найденных на живой подписке
коллизий (см. историю ниже):

```sh
name_slug="$(slugify "$name" | cut -c1-12)"
line_hash="$(printf '%s' "$line" | md5sum | cut -c1-10)"
tag="sr_${label_slug}_$(slugify "$host")_${port}_${name_slug}_${line_hash}"
```

([`lib/subscription.sh:391-393`](../../lib/subscription.sh#L391-L393))

Три коллизии, найденные на реальной подписке (152 узла), в порядке
эскалации фикса:

1. **`host+port+secret`** — недостаточно: провайдер переиспользует один
   и тот же endpoint+credential для нескольких разных узлов, отличающихся
   только transport-путём/SNI (несколько CDN-граней перед одним VLESS-сервером)
   — 70 импортированных серверов схлопнулись в 56.
2. **`+ имя (slugify)`** — тоже недостаточно: `slugify()` мапит **любой**
   не-ASCII символ в `_` и схлопывает повторы — полностью кириллическое имя
   (обычное дело для RU-маркет подписки) может свестись к одной цифре или
   вообще пустоте, тихо смерджив разноимённые узлы, если оба заканчиваются
   одинаково (например оба "... 1"). Плюс усечение секрета до 8 символов
   тоже не хватает — в этой же подписке несколько разных UUID расходятся
   только *после* 8-го символа.
3. **Финал: хеш всей сырой строки** — единственное, что гарантированно
   уникально ровно тогда, когда узлы реально разные (совпадёт, только
   если исходные строки байт-в-байт идентичны — тогда это один и тот же
   тег, что и правильно). `name_slug` остаётся в теге только ради
   читаемости при просмотре сгенерированного конфига, уникальность даёт
   исключительно хеш.

## match_key: отдельная, более грубая идентичность

Тег специально **меняется**, стоит провайдеру поменять хоть один
query-параметр — но профиль, ссылающийся на старый тег, должен пережить
обычный refresh, если это тот же узел. Для этого есть отдельное поле
`match_key` — грубее тега, устойчивее к мелким правкам:

```sh
match_sni="$(urldecode "$(qval "$query" sni)")"; [ -n "$match_sni" ] || match_sni="$host"
match_key="$(printf '%s|%s|%s|%s' "$host" "$port" "$secret" "$match_sni" | md5sum | cut -c1-16)"
```

([`lib/subscription.sh:408-409`](../../lib/subscription.sh#L408-L409))

`host+port+secret+camouflage-домен` (sni, с фолбэком на host) — это то,
что реально определяет "тот же логический узел" у провайдера; путь,
padding/xmux-тюнинг, порядок alpn, fp, отображаемое имя — то, что
провайдер может подправить *у того же* узла не по злому умыслу, поэтому
в ключ не входит. `sni` обязателен в ключе, а не только host: подтверждено
на этой же подписке, что два узла могут делить host+port+secret и
отличаться только этим доменом (реально разные грани), так что без него
`match_key` их бы неправомерно смерджил.

Что дальше делает `match_key` при фактическом refresh — отдельный,
большой механизм, описанный в [subscription-update.md](subscription-update.md).

## Атомарность импорта: блокировка и пустой ответ

Два реальных бага, оба найдены вживую и закрыты в одном месте.

**Гонка одновременных импортов.** SSH-таймаут на клиенте один раз оставил
`refresh-one` работать на роутере уже после того, как вызывающая сторона
сдалась и повторила запрос — два параллельных процесса писали в одни и те
же временные файлы и результат съехал со 130 серверов до 26. `mkdir` —
атомарная операция на любой файловой системе, которую использует этот
проект (тот же приём, что и regen-lock в `genroute.sh`), но, в отличие от
него, этот лок **ждёт**, а не пропускает попытку:

```sh
lock_dir="$SR_STATE_DIR/.import.lock"
waited=0
while ! mkdir "$lock_dir" 2>/dev/null; do
	lock_age=999999
	[ -d "$lock_dir" ] && lock_age=$(( $(date +%s) - $(date -r "$lock_dir" +%s 2>/dev/null || echo 0) ))
	if [ "$lock_age" -ge 300 ]; then
		sr_log "reclaiming stale import lock (${lock_age}s old)"
		rm -rf "$lock_dir"; continue
	fi
	[ "$waited" -lt 120 ] || sr_die "another subscription import is already running and didn't finish within 120s"
	sleep 2; waited=$((waited + 2))
done
trap 'rm -rf "$lock_dir"' EXIT INT TERM
```

([`lib/subscription.sh:297-313`](../../lib/subscription.sh#L297-L313))
Явный "Обновить сейчас", гоняющийся с часовым cron-рефрешем, всё равно
должен реально импортировать — не молча ничего не делать только потому,
что кто-то другой оказался первым.

**Пустой/битый ответ не должен стирать существующие данные.** Успешный
(`curl` exit 0) запрос может вернуть пустое тело, страницу с ошибкой, или
тело без единой распознаваемой `vless://`/`trojan://` строки — без явной
проверки это тихо стёрло бы весь список серверов этого лейбла на
следующем шаге merge:

```sh
parsed_count="$(jq 'length' "$tmp_servers")"
if [ "$parsed_count" -eq 0 ]; then
	sr_log "import '$label' fetched 0 usable server(s) (empty/invalid response?) -- keeping existing data untouched"
	rm -f "$tmp_outbounds" "$tmp_servers" ...
	return 1
fi
```

## ARG_MAX: почему outbounds пишутся через файл, а не аргумент

Реальная подписка на тестовом роутере — 150+ серверов. Ранняя версия
кода пыталась протащить весь массив outbounds через `--argjson` как
аргумент командной строки — и падала на ОС-лимите `ARG_MAX`
("Argument list too long"). Хуже того, `>` усекает целевой файл ещё
**до** того, как команда вообще выполнится — то есть падение оставляло
`04_outbounds.smartroute.json` **нулевого размера**, а значит Xray без
единого outbound'а. Финальная версия читает состояние прямо из файла
(`jq '...' "$SR_OUTBOUNDS_STATE_FILE"`, без прогона через аргумент
шелла) и пишет во временный файл перед атомарным `mv`
([`lib/subscription.sh:504-515`](../../lib/subscription.sh#L504-L515)) —
закрывает и лимит размера, и риск оставить обрезанный файл при любом
сбое на середине записи.

## Пинг: почему последовательно, а не параллельно

`sr_ping_one()` меряет **TCP connect-время** через
`curl -w '%{time_connect}'` — не настоящий ICMP-пинг (нужны root-права,
многие сети/сервера его режут), и не зависит от того, успеет ли
завершиться TLS/VPN-рукопожатие (для голого GET к VLESS/Trojan-эндпоинту
оно и не должно).

Пробники идут **строго последовательно**, не пачкой. Причина —
подтверждённая вживую на тестовом роутере (~250MB RAM, без swap): запуск
многих параллельных проверок одновременно (та же ошибка, что
`enableConcurrency` у самого Xray Observatory, см.
[balancer.md](balancer.md#сознательные-ограничения)) поднимает нагрузку и
память достаточно, чтобы получить ложные таймауты или что похуже. Для
большой подписки это медленнее, но не врёт и не рискует OOM.
