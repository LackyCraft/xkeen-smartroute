# Автообновление списков доменов, которых нет в geosite

Как устроен `scripts/update_lists.py` и workflow `update-domain-lists.yml` —
то, что стоит за пунктом README «Списки доменов, которых нет в geosite».

## Зачем

Xray-core берёт домены из **geosite** ([v2fly/domain-list-community](https://github.com/v2fly/domain-list-community)).
По состоянию на 2026-08-20 там нет отдельных категорий для **Character.AI**,
**Grok/x.ai**, **npm registry** — для них в репозитории свои списки
`lists/custom/*.lst`, которые SmartRoute предлагает в выборе домен-списка
профиля (помечены «нет в geosite»).

(ChatGPT/OpenAI и Claude/Anthropic уже есть в geosite как `openai` и
`anthropic` — отдельно поддерживать не нужно.)

## Источник кандидатов

`scripts/seeds.json` — по одному объекту на сервис:

```json
{
  "services": {
    "character-ai": {
      "label": "Character.AI",
      "routing": true,
      "candidates": ["character.ai", "beta.character.ai", "..."]
    }
  }
}
```

`routing: true` — домены сервиса реально используются для маршрутизации
(попадают в `lists/custom/<key>.lst`). `routing: false` — только IP-снимок
(см. ниже), в выборе домен-списков профиля не участвует.

## Проверка живости (`check_domain`, `scripts/update_lists.py`)

Не голый DNS-résolve — TCP+TLS хендшейт на порт 443 (реальный ICMP-пинг
слишком часто блокируется на CI-раннерах, ненадёжный сигнал). До 3 попыток
на домен — единичный сетевой сбой не должен выкидывать рабочий домен из
списка и плодить лишний релиз с шумным diff'ом.

## Что пишется, куда

- **`lists/custom/<key>.lst`** — только для `routing: true`, только живые
  на этом прогоне домены. Это то, что реально попадает в маршрутизацию.
  Мёртвые (не прошедшие проверку) кандидаты перечислены в комментарии в
  начале файла, не молча выбрасываются из `seeds.json`.
- **`lists/ip/<key>.lst`** — для *всех* сервисов из `seeds.json` (не только
  `routing: true`) — резолвленные IPv4 как датированный снимок. **Справочный
  файл, не маршрутизация**: у CDN-сервисов адреса ротируются постоянно,
  разовый DNS-снимок ничего не гарантирует — реальная маршрутизация всегда
  идёт по домену.

Файлы перезаписываются только если состав реально изменился (сравнение
множеств строк) — незначащий шум (порядок строк, whitespace) не создаёт
лишних коммитов.

## Публикация

`.github/workflows/update-domain-lists.yml`: по понедельникам (`17 4 * * 1`
UTC) и по кнопке (workflow_dispatch). Если что-то изменилось —
коммитит `lists/custom` + `lists/ip` и публикует GitHub Release с тегом
`lists-ГГГГ-ММ-ДД-N` (`N` — номер прогона, на случай повторного ручного
запуска в тот же день), с changelog по каждому сервису
(`+добавлено`/`-убрано`, отдельно для домен-списка и IP-снимка). Это
отдельный канал релизов от версий приложения (`vX.Y.Z`) — не задевает
историю версий, см. [docs/release-process.md](../release-process.md)
«Разделение каналов релизов».

## Добавить список для своего сервиса

- **Через PR**: добавить кандидатов в `scripts/seeds.json`, пайплайн сам
  проверит и соберёт файл.
- **Прямо на роутере, без GitHub**: вкладка «Домены» (панель SmartRoute) /
  «Профили» (LuCI) → «Добавить свой домен(ы)».
