# Установка на KeeneticOS

Инструкция для тех, кто ставит XKeen SmartRoute на роутер Keenetic
(KeeneticOS). В отличие от OpenWrt, Entware (`/opt`, `opkg`) на KeeneticOS
не может жить на встроенной flash-памяти роутера — места там всего
несколько десятков мегабайт, а стеку (Entware + Xray-core + панель +
списки доменов) нужно 60–100+ МБ. Поэтому обязателен внешний
USB-накопитель.

Проверено вживую на **Keenetic Hero 4G+ (KN-2311)**, до конца — от чистой
флешки до рабочего shell в Entware. Источники: официальная статья
Keenetic про OPKG
([support.keenetic.ru](https://support.keenetic.ru/hopper/kn-3811/ru/20980.html))
и практическое руководство
[Corvus-Malus/XKeen](https://github.com/Corvus-Malus/XKeen#установка-системы-пакетов-репозитория-entware-на-usb-накопитель).

## Шаг 1. Подготовьте флешку

1. Возьмите любую чистую USB-флешку.
2. Отформатируйте её в файловую систему **ext4** на компьютере —
   Windows не умеет это штатными средствами, нужен сторонний
   инструмент: **[Paragon Partition Manager Free](https://www.paragon-software.com/free/pmf-express/)**
   или **[AOMEI Partition Assistant Standard](https://www.aomeitech.com/pa/standard.html)**
   (на Mac — `e2fsprogs` через Homebrew, `mkfs.ext4`).
3. Вставьте отформатированную флешку в свободный USB-порт роутера.

## Шаг 2. Включите компоненты KeeneticOS

Веб-интерфейс роутера (по умолчанию `192.168.1.1`) → **Общие настройки**
→ **Обновления и компоненты** → **Изменить набор компонентов**. Отметьте:

- **Файловая система ext**
- **Утилиты для файловой системы ext**
- **Интерфейс USB**
- **Общий доступ к файлам и принтерам по протоколу SMB**
- **Поддержка открытых пакетов**
- **Прокси-сервер DNS-over-TLS**
- **Прокси-сервер DNS-over-HTTPS**
- **Модули ядра подсистемы Netfilter**
- **Сервер SSH** — нужен временно, чтобы попасть в CLI роутера и провести
  установку; после того, как Entware поднимет свой SSH (шаг 5), этот порт
  освобождается командой на шаге 5.

**Сохранить**.

## Шаг 3. Подключитесь к роутеру по SSH

PuTTY / Termius / MobaXterm (или любой SSH-клиент) → IP роутера, порт
**222**, логин `admin`, пароль — обычный пароль веб-интерфейса роутера.

Это даёт ограниченный CLI KeeneticOS (не полноценный shell) — этого
достаточно для шагов 4–5.

Если после нескольких неудачных попыток подключение перестало отвечать —
это не неверный пароль, а защита от перебора (блокировка на несколько
минут после 5 неудачных попыток) — подождите и попробуйте снова.

## Шаг 4. Загрузите установщик Entware на флешку

Флешка (уже в роутере, ext4, см. шаг 1) видна по сети через SMB — на
компьютере с Windows откройте её в Проводнике по адресу
`\\<IP роутера>\<метка_флешки>` (Приложения → Диски и принтеры в
веб-интерфейсе роутера покажет точный путь и метку).

1. Скачайте архив установщика под архитектуру вашей модели:
   - большинство MIPS-моделей (в т.ч. Hero 4G/4G+, Giga, Extra, Ultra,
     Viva, Omni, Duo) — [`mipsel-installer.tar.gz`](https://bin.entware.net/mipselsf-k3.4/installer/mipsel-installer.tar.gz)
   - DSL/Skipper/Hopper DSL и т.п. — [`mips-installer.tar.gz`](https://bin.entware.net/mipssf-k3.4/installer/mips-installer.tar.gz)
   - новые модели на aarch64 (Peak, Hopper, Giga III и т.п.) —
     [`aarch64-installer.tar.gz`](https://bin.entware.net/aarch64-k3.10/installer/aarch64-installer.tar.gz)
   - точный список моделей под каждый архив — в README
     [Corvus-Malus/XKeen](https://github.com/Corvus-Malus/XKeen#установка-системы-пакетов-репозитория-entware-на-usb-накопитель)
2. На флешке (в её корне) создайте папку **`install`**.
3. Скопируйте туда скачанный архив (`mipsel-installer.tar.gz` и т.п.).

## Шаг 5. Установите Entware через страницу OPKG

Веб-интерфейс роутера → **Менеджер пакетов OPKG** (в старых версиях
прошивки — **Приложения → OPKG**):

1. Поле **Накопитель** — выбираем ext4-раздел нашей флешки.
2. Поле **initrc** — оставляем **пустым** (заполнится автоматически по
   завершении установки).
3. **Сохранить**.

Установка идёт в фоне на роутере (заняла порядка 5 минут на реальном
Hero 4G+ по USB 2.0). Прогресс — в **Диагностика → Системный журнал**:
последовательно `[1/5]` … `[5/5]`, в конце —
`Установка системы пакетов "Entware" завершена!`.

**Важный нюанс, если оставили "Сервер SSH" включённым (шаг 2):** dropbear
самого Entware при первом старте попытается занять порт **222** и
получит `Address already in use` (порт уже занят SSH-сервером
KeeneticOS) — тогда после установки порт 222 будет молчать. Освободите
его, переместив SSH-сервер KeeneticOS на другой порт, и подтолкните
Entware переинициализироваться, переключив накопитель на странице OPKG
(снять галку **Накопитель** → Сохранить → выбрать накопитель снова →
Сохранить) — либо то же самое через CLI (см. шаг 3):

```
ip ssh port 2222
```
(CLI KeeneticOS будет теперь на 2222; переключение накопителя на OPKG
можно повторить через веб-интерфейс).

## Шаг 6. Подключитесь к Entware

PuTTY / Termius / MobaXterm → IP роутера, порт **222**, логин `root`,
пароль **`keenetic`** (дефолтный пароль Entware — смените его при первом
входе командой `passwd`).

Проверка, что это уже настоящий Entware, а не CLI KeeneticOS:

```sh
uname -a
opkg --version
opkg update && opkg upgrade
```

На этом Entware готов — дальше можно ставить сам XKeen SmartRoute.

## Установка SmartRoute

По SSH на Entware (не на CLI KeeneticOS — см. шаг 6 выше), порт 222,
логин `root`:

```sh
wget -q -O - https://raw.githubusercontent.com/LackyCraft/xkeen-smartroute/master/install.sh | sh
```

Обычный pipe, а не `sh <(wget ...)` из README для OpenWrt — process
substitution (`<(...)`) не работает в shell этого Entware (нет `/dev/fd`).
Сам `install.sh` не меняется, меняется только то, как его запускают.

`install.sh` сам определяет платформу (по `uname -r`, ищет `-ndm-`) и
понимает, что Entware уже стоит — не пытается ставить его заново, только
проверяет. Дальше по шагам install.sh (1–6) ставит xkeen, xkeen-UI (порт
1000) и панель smartroute-gateway (порт 1001), генерирует конфиги Xray,
настраивает cron.

**Проверено вживую на Keenetic Hero 4G+ (KN-2311): базовый стек
устанавливается и работает** — xkeen, Xray (пакет Entware `xray_s`,
ставится самим мастером `xkeen -i`, без хардфлоат-краша, который бывает
на OpenWrt), панель на порту 1001 (`curl 127.0.0.1:1001/version` отвечает
корректным JSON), подписки/профили/списки доменов хранятся в
`/opt/etc/xkeen-smartroute` (на KeeneticOS `/etc` доступен только для
чтения — это не overlay, как на OpenWrt, а squashfs-образ прошивки, так
что этот каталог не может быть `/etc/xkeen-smartroute`, как на OpenWrt).

**Работает на KeeneticOS** (проверено вживую): прозрачный перехват
LAN-трафика (вкладка «Защита от утечек») — на KeeneticOS у него отдельный
бэкенд поверх легаси `iptables`/`ip6tables` (то же самое пространство
правил, которым управляет NDM-firewall самого роутера — на KeeneticOS нет
`uci`/`nftables`/`fw4`, как на OpenWrt). Включение перехвата, защита от
утечек DNS/IPv6/QUIC и опциональная «защита от отказа Xray» (fail-closed)
работают так же, как на OpenWrt — только правила пишутся напрямую в
iptables, а не в управляемый `.nft`-файл. Подробности механики —
[docs/functionality_doc/leak-protection.md](functionality_doc/leak-protection.md).

**Пока не поддержано на KeeneticOS** (в разработке):

- **LuCI-модуль** — на KeeneticOS нет LuCI вообще, `install.sh` его
  пропускает. Панель `:1001` и xkeen-UI `:1000` — единственный UI.
- **Жёсткий (per-профильный) kill-switch** — `lib/killswitch.sh`
  построен на ipset/nftset-поддержке системного `dnsmasq` и на
  `fw4`/`nftables.d`, которых на KeeneticOS нет ни в каком виде — нужен
  отдельный порт под NDM-firewall KeeneticOS, отдельная от перехвата
  задача.

Два нюанса самого KeeneticOS/Entware, обнаруженные по пути (актуальны
при запуске команды выше и любых `wget`-вызовов вручную на этой
платформе):

- **`sh <(wget ...)` (process substitution) не работает** — см. команду
  установки выше, поэтому там обычный pipe.
- **`wget` без флага `-ssl` в `$PATH` резолвится не в тот бинарник** —
  `/opt/usr/bin/wget` (без SSL, входит в `opt-ndmsv2`) стоит в `$PATH`
  раньше `/opt/bin/wget` (символическая ссылка на `wget-ssl`). `install.sh`
  сам ставит `wget-ssl`/`ca-certificates` и расширяет `$PATH` в правильном
  порядке в самом начале — актуально только если вызываете `wget` вручную
  до этого момента.
