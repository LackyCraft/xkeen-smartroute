# Если провайдер блокирует GitHub/CDN во время установки

`install.sh`/`uninstall.sh` качают файлы с нескольких внешних хостов —
`raw.githubusercontent.com` (сам скрипт, `lib/*.sh`, LuCI-модуль, списки
доменов), `github.com`/`objects.githubusercontent.com` (бинарник панели из
GitHub Releases), `bin.entware.net` (Entware), `downloads.openwrt.org`
(пакеты `opkg`, например `dnsmasq-full`). Если провайдер режет DPI-фильтром
конкретные CDN — команда либо зависает намертво, либо падает с таймаутом,
при этом обычный интернет (`ping 8.8.8.8` и т.п.) работает нормально.

Ниже — как это опознать и обойти, не трогая сам роутер и не дожидаясь,
пока провайдер снимет блокировку.

## Как понять, что дело именно в этом

```sh
# обычный интернет работает
ping -c 2 8.8.8.8

# а конкретный хост — нет (TLS-хендшейк зависает/таймаутит)
curl -v --max-time 5 https://raw.githubusercontent.com/
```

Если `ping 8.8.8.8` отвечает, а `curl` до конкретного хоста висит до
таймаута (не "connection refused", а именно тишина) — это DPI-блокировка
по SNI/IP, а не поломка сети. `wget -O -` в связке с `sh <(...)` в такой
ситуации допечатывает `Redirecting output to 'wget-log.N'` и зависает —
это нормальное поведение `wget` при неинтерактивном stdout, само по себе
не ошибка, просто маскирует происходящее.

Частая деталь: `raw.githubusercontent.com` и `downloads.openwrt.org`
оба хостятся на Fastly (anycast-CDN) — если заблокирован один, скорее
всего заблокирован и другой, и любой третий хост на той же
инфраструктуре. `github.com`/`objects.githubusercontent.com` (бинарник
gateway с GitHub Releases) обычно на **другой** инфраструктуре и
блокировки может не быть вообще — проверьте отдельно, не факт что нужен
туннель и для него тоже.

## Обход: SSH-туннель с компьютера, у которого интернет работает

Идея: не трогать сам роутер, а временно "одолжить" ему интернет с любого
компьютера, у которого нет этой блокировки (даже если он в другой сети —
нужен только SSH-доступ до роутера). Реализуется штатным `ssh -R`, без
дополнительного софта — только сам SSH-клиент.

**Шаг 1 — узнайте реальный IP заблокированного хоста** (с самого роутера
или с любого другого места, где DNS ещё не тронут блокировкой):

```sh
nslookup raw.githubusercontent.com
```

**Шаг 2 — с компьютера с рабочим интернетом откройте обратный туннель**
(держите эту сессию открытой на всё время установки):

```sh
ssh -N -R 127.0.0.1:18443:raw.githubusercontent.com:443 root@<IP роутера>
```

- `-N` — не открывать shell, только форвардинг.
- `127.0.0.1:18443` — порт **на роутере**, куда всё будет прилетать
  (не 443 — dropbear на роутере обычно отказывает в бинде на
  привилегированные порты <1024 даже под root'ом; любой свободный порт
  ≥1024 подойдёт).
- `raw.githubusercontent.com:443` — куда реально стучаться **с той
  стороны**, где интернет работает.

Если получите `TCP forwarding request denied` — тот же случай, порт
занят или ниже 1024, возьмите другой.

**Шаг 3 — на самом роутере (вторая SSH-сессия) заверните реальный
трафик до заблокированного хоста в этот туннель:**

```sh
# IP из шага 1, может быть несколько -- добавьте правило на каждый,
# либо на весь диапазон, если он известен (для raw.githubusercontent.com
# это 185.199.108.0/22 -- Fastly, тот же для GitHub Pages)
nft add table inet gh_tunnel
nft 'add chain inet gh_tunnel output { type nat hook output priority -100 ; }'
nft add rule inet gh_tunnel output ip daddr 185.199.108.0/22 tcp dport 443 redirect to :18443
```

**Шаг 4 — проверьте и пользуйтесь установкой как обычно:**

```sh
curl -s -o /dev/null -w '%{http_code}\n' https://raw.githubusercontent.com/LackyCraft/xkeen-smartroute/master/README.md
# должно быть 200
sh <(wget -q -O - https://raw.githubusercontent.com/LackyCraft/xkeen-smartroute/master/install.sh)
```

Если блокирует ещё и `downloads.openwrt.org` (обычно проявляется как
зависание на шаге `dnsmasq-full`) — повторите шаги 1-3 для него отдельно,
на **другом** локальном порту (например `18444`), с отдельным правилом
`nft`.

## После установки — уберите за собой

Туннель и правило `nft` не сохраняются в конфиге проекта и не переживают
перезагрузку — но если делаете это на живом роутере, а не тестовом,
уберите вручную сразу после установки, не дожидаясь перезагрузки:

```sh
nft delete table inet gh_tunnel
```
и закройте SSH-сессию с `ssh -R` на компьютере с интернетом (`Ctrl+C`).

## Если ничего из этого не помогает

- Убедитесь, что провайдер не режет TLS ClientHello по SNI ещё где-то
  ниже по пути (например, на уровне вышестоящего роутера, если этот
  роутер сам сидит за другим — `ip route show default` покажет, если
  шлюз не похож на прямой ISP-адрес).
- Попробуйте временно сменить DNS роутера на `1.1.1.1`/`8.8.8.8` — не
  поможет против блокировки по IP, но исключит DNS-подмену как отдельную
  причину.
- Если блокировка касается только `raw.githubusercontent.com`, а
  `github.com` не блокирован — узнайте, у какого хоста CDN и IP-адрес
  ближе к разблокированному (`objects.githubusercontent.com` часто на
  другой инфраструктуре, не Fastly) и решайте по обстановке — точный
  список хостов install.sh трогает, см. `REPO_RAW`/`XKEEN_UI_REPO`/
  `GATEWAY_RELEASE_BASE` в начале `install.sh`.
